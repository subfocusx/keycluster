# KeyCluster — конкурентный анализ и план улучшений интерфейса

Дата: 2026-11-05. Основан на визуальном аудите текущего UI (1600×950 и 1280×800), прогоне всех вкладок
ленты и 17 плагинов, а также на сравнении с аналогичными продуктами.

## 1. Аналоги и референсы

### 1.1. Десктопные SEO-инструменты (ближайшие конкуренты)

| Продукт | Что сделано хорошо (что стоит взять) | Чего не хватает / чем KeyCluster лучше |
|---|---|---|
| **Key Collector** (КК) | Мощнейшее дерево папок + таблица запросов, массовые операции над выделенными строками, «разгруппировать запрос», теги и метки, группировка по составу фраз с историей | Десктоп, тяжёлая установка, нет веб-версии |
| **Topvisor** | «Карта интерфейса»: запросы, папки, проекты, KPI проекта, массовые операции, раздельные «Кластеры» и «Группы» | Онлайн, часть функций за paywall |
| **SpySERP Keyword Grouper** | **Drag & drop** слов между кластерами, несколько независимых наборов группировки с разными настройками, мгновенный пересчёт | Ограниченный набор метрик |
| **Semrush Keyword Strategy Builder** | Иерархия **Topics → Pillar Pages → Subpages** — та же модель, что и в KeyCluster, плюс привязка к целевым URL | Привязка к домену и SERP, у нас — офлайн-алгоритмы |
| **Ahrefs Keywords Explorer** | Плотная таблица с метриками (volume, KD, CPC, clicks), сортировки по любой колонке, «Keyword Difficulty» как визуальный бейдж | Нет ручной работы с деревом групп |
| **Search Atlas / RankTree / keywordly** | Сценарий «CSV → готовая структура за 3 шага»: загрузил → сгруппировано → скачал карту топиков | Одноразовый пайплайн, нет ручной доводки |
| **Keyword Insights / SE Ranking** | Порог близости SERP как ползунок, метрики «объём кластера», рекомендация целевой страницы | — |

### 1.2. Смежные инструменты с сильным UX (паттерны, а не функциональность)

| Продукт | Паттерн |
|---|---|
| **OpenRefine** | Фасетная навигация (счётчики у каждого значения), кластеризация с **живым предпросмотром** и отменой, персистентные фасеты, «одна кнопка — действие» |
| **Excel / AG Grid** | Виртуализация, закрепление колонок, контекстное меню на строке, множественное выделение с Shift/Ctrl, «выделено N из M» |
| **VS Code** | Breadcrumbs (путь в дереве), command palette (Ctrl+K), дерево с вертикальными линиями-отступами, inline-переименование |
| **Figma / Miro** | Drag & drop, «предпросмотр перед применением», undo/redo как единственный источник правды |

### 1.3. Вывод

KeyCluster уже умеет то, чего нет у большинства конкурентов: **офлайн-алгоритмы + ручная доводка структуры + минус-фразы с областями видимости + корзина**. Но интерфейс пока «инженерный»: он показывает состояние, а не помогает принимать решения. Ниже — что конкретно мешает работать.

| U12 | Нет сохранения «рабочих представлений»: каждый раз заново настраивать столбцы/фильтры под задачу | тулбар | Повторяющаяся ручная работа |
| U13 | Пустая таблица при фильтрах показывала «группа пуста» (исправлено) | — | — |
| U14 | Нет индикации прогресса/оценки времени для долгих операций (кластеризация на 100k+ фраз) | «Кластеризация» | Страх нажать «Старт» на большом проекте |
| U15 | Нет экспорта в универсальный формат (TXT/CSV по группе) прямо из дерева | панель групп | Копирование руками |

## 4. Приоритизированный план улучшений

### P0 — заметный эффект, умеренная сложность (1–3 дня)

**P0.1. Drag & drop фраз и групп** *(аналоги: SpySERP, VS Code, Figma)*
- Фразу из таблицы перетаскивать в группу в дереве; группу — в другую группу (смена родителя).
- Индикатор зоны приёма, отмена перетаскивания по Esc, подсветка цели.
- Файлы: `src/modules/groups/GroupItem.tsx` (drop-target), `src/modules/phrases/PhraseRow.tsx` (drag-source), новый `src/core/dnd/groupDnd.ts`.
- Приёмка: фраза, перетащенная в группу, меняет `groupId`; дерево принимает drop при перетаскивании группы в другую; всё через `movePhrases`/`moveGroup` с записью в undo.

**P0.2. Панель групп: сворачивание, видимая ручка, режим «дерево слева»**
- Панель уже растягивается мышью, но ручка была 1 px без подсказки, а сама панель не сворачивается.
- Сделать ручку заметной (сделано в этом прогоне), добавить кнопку «свернуть панель» и опцию «дерево слева» (по аналогии с Excel/VS Code/Key Collector).
- Файлы: `src/shell/PanelManager.tsx`, `src/modules/groups/GroupsPanel.tsx`, `src/core/store/uiSlice.ts`.
- Приёмка: при ширине окна 1280 px таблица показывает все колонки без горизонтального скролла; ширину панели видно и можно менять мышью; панель сворачивается в иконку; настройка сохраняется в проекте.

**P0.3. Чистые счётчики в дереве групп** *(аналоги: OpenRefine faceted browsing)*
- Бейдж минус-фраз со значением «0» убран из постоянного показа (виден при наведении/активной группе) — сделано в этом прогоне.
- Осталось: рядом с числом фраз показывать, что именно оно значит, и добавить сводку по клику («2 фразы · 1 минус-фраза · 3 подгруппы»).
- Файлы: `src/modules/groups/GroupItem.tsx`, `GroupsPanel.tsx`.
- Приёмка: без наведения пользователь понимает, что означает каждое число.

**P0.4. Полное имя группы без обрезки + поиск по дереву с подсветкой совпадений**
- `title` есть, но текст обрезан: показывать полное имя в тултипе и подсвечивать совпадения в строке поиска групп.
- Файлы: `GroupsPanel.tsx`, `groups-filter.tsx`.

**P0.5. «Что отменит undo»**
- Добавить в `UndoSnapshot` человекочитаемый `label` («Перенос 6 фраз в «Кластеры»», «Удаление 1 дубля»), показывать в подсказке статус-бара и в палитре команд.
- Файлы: `src/core/store/undoSlice.ts`, `src/shell/status-bar.tsx`.
- Приёмка: наведение на «↩ 3» показывает список последних 3 действий; клик — отменяет нужное.

### P1 — сильный эффект, средняя сложность (3–7 дней)

**P1.1. Предпросмотр перед применением для всех разрушающих операций**
- Дедупликатор, неявные дубли, минус-фразы, «Найти/Заменить» — сейчас часть уже показывает превью; довести до единого шаблона: список «что изменится» + «Применить / Отмена» (по аналогии с OpenRefine «Cluster» и подтверждениями в Ahrefs).

**P1.2. Панели как dock, а не модальные окна**
- Инструменты (Анализ групп, N-граммы, TF-IDF, AI) — боковые док-панели, а не модальные диалоги: результат виден рядом с таблицей, можно свернуть.
- Файлы: `src/shell/PanelManager.tsx`, `src/components/modals/ToolModal.tsx`.

**P1.3. Рабочие представления (presets)**
- Сохранить набор: столбцы + порядок + ширины + фильтры + сортировка как «Представление» (например, «Кластеризация», «Минус-фразы», «КПТ»). Переключение — одним кликом из тулбара.
- Файлы: `src/core/store/uiSlice.ts`, `PhrasesToolbar.tsx`, `project-types.ts` (сохранение в проекте).

**P1.4. Индикатор прогресса и оценка времени для тяжёлых операций**
- Кластеризация/дедупликация на больших объёмах: прогресс-бар, «обработано N из M», кнопка отмены (в текущем Worker).
- Файлы: `src/core/clustering/*`, `user-plugins/deduplicator/components.tsx`.

**P1.5. Массовые операции по образцу выделения**
- «Выделить по совпадению», «Выделить все с меткой X», «Применить действие ко всем результатам фильтра» — сейчас выделение только кликами/Ctrl.

**P1.6. Экспорт группы в CSV/TXT из дерева и буфер обмена**
- Контекстное меню группы → «Экспорт фраз (CSV/TXT)», «Скопировать список». Аналогия: Key Collector, Topvisor.

### P2 — развитие (1–3 недели)

**P2.1. Встроенная проверка качества кластера с рекомендациями**
- Интент, разброс, «похожие группы, которые стоит объединить», «пустые/одиночные группы» — в виде actionable-подсказок (аналогия: Ahrefs KD, Search Atlas SERP-фичи, кластер-качество уже есть в KeyCluster — нужно вывести в UI).

**P2.2. «Слои» группировки**
- Как в SpySERP: несколько независимых наборов кластеров (по SERP / по составу / вручную) с переключением и сравнением. Основа — уже существующая модель групп.

**P2.3. Совместная работа / экспорт отчёта**
- Shareable HTML/PDF-отчёт по проекту (для клиентов) — аналогия: Ahrefs/Topvisor отчёты.

**P2.4. Онбординг**
- Короткий мастер «Импорт → кластеризация → минус-фразы → экспорт» с подсказками в пустых состояниях (сейчас пустые состояния частично это делают).

**P2.5. Доступность и плотность**
- Фокус-кольца, ARIA-роли для дерева (tree/treeitem), режим «плотная таблица», горячие клавиши для выделения (Ctrl+A, Shift+↑/↓), переключаемая плотность строк.

## 5. Мелочи, которые делают интерфейс «взрослым»

1. **Подсказки (tooltips) на всех иконах** — сейчас есть у большинства, но не у всех (проверить единообразие).
2. **Единый формат чисел** — `toLocaleString('ru')` везде: сейчас в разных местах смешаны «12» и «12,3».
3. **Подтверждение для массовых операций** — всегда показывать «N фраз из M групп» (уже исправлено в одном месте, применить ко всем диалогам).
4. **Пустое состояние правой панели** — подсказка «Перетащите фразу сюда», когда таблица пуста.
5. **Индикатор несохранённых изменений рядом с именем проекта**, а не только в статус-баре.

---

## 6. Как измерять эффект

- Время от «импорт CSV» до «структура готова» (сейчас: ручной набор групп — доминирующийcost).
- Доля операций, отменённых через undo (высокая доля = плохой предпросмотр).
- Число ошибок пользователя при перемещении фраз (прослеживается по «переместить в корзину → восстановить»).
- Время до первого результата после запуска кластеризации (нужен прогресс).
- Количество открытых «пустых» панелей → цель: снизить за счёт P1.2.

## 7. Рекомендуемый порядок

1. Сначала **P0.2 + P0.3 + P0.4** — это чистка читаемости без переделки логики (1–2 дня).
2. Затем **P0.1 (drag & drop)** — самый большой выигрыш в скорости работы (3–5 дней).
3. Параллельно **P0.5 + P1.1** — доверие к изменениям.
4. Далее **P1.2 / P1.3** — переход от «инженерного» интерфейса к рабочему пространству.
5. P2 — по мере роста аудитории.
